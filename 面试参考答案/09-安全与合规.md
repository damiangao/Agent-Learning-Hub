# 九、安全与合规（参考答案）

---

**Q132. Prompt injection：为什么没有完整解法？**

一句话：直接注入 = 用户输入里藏指令（"忽略以上规则"）；间接注入 = 恶意指令藏在模型要处理的外部内容里（网页、邮件、检索文档、图片）。无完整解法的根因：模型把系统指令、可信内容、不可信数据作为**同一串 token** 处理，没有"特权通道"区分指令与数据——指令和数据在架构层面就分不开。

展开：因此防御是**分层降险**而非根除：① 输入侧——来源信任分级，外部内容明确标记为数据（Q21）；② 权限侧——最小权限让注入"即使成功也造不成大祸"（最重要的一层，Q69/Q77）；③ 行为侧——敏感操作人工确认；④ 输出侧——外发内容过滤审计。答这题的态度分：说"加个过滤就行"是没理解；说"无法根除，所以按最坏情况设计权限"是对的。OWASP LLM Top 10 里提示注入 2023 和 2025 两版都排第一。

---

**Q133. OWASP LLM Top 10（2025）有哪些？**

一句话：记得住的头几项：LLM01 提示注入、LLM02 敏感信息泄露、LLM03 供应链（依赖/模型/微调数据投毒）、LLM04 数据与模型投毒、LLM05 不当输出处理（把 LLM 输出直接拼进 SQL/命令=新式注入）、LLM06 过度授权（agent 权限过大）、LLM07 系统提示泄露、LLM08 向量/嵌入弱点（RAG 跨租户检索等）、LLM09 错误信息（误导用户的虚假内容）、LLM10 无限消耗（无限循环烧钱）。

展开：不必背全表，答出"前三位是什么 + 说出 2~3 个和你业务相关的场景"即可。真正加分的是把条目串到自己的架构上："我们的 agent 系统对应 01/02/06/10 四个风险，分别有 XX 防线"——把清单变成 checklist 的意识比背书值钱。

**Q134. 数据发给第三方 API 的泄露风险怎么管？**

一句话：四道闸：① 分类分级——什么数据允许出域（公开内容）什么绝不允许（用户 PII、商业机密），默认禁止；② 技术脱敏——出域前 PII 识别替换（假名化），回来还原；③ 合同与配置——企业协议明确"零保留/不用于训练"、数据区域选择、处理用途限定；④ 技术验证——出域流量审计（防组件绕过协议偷传）。

展开：常见的盲区：① prompt 里嵌的用户数据（客服系统把工单全文塞 prompt）——脱敏要作用在 prompt 组装层；② 日志与 trace 里同样有敏感数据，落库也要脱敏和加密；③ 子处理商（API 供应商再调上游模型）——供应链问清楚。加分点："数据出域决策要做成架构层开关（按租户/场景可配），而不是散在各处的人工判断。"

**Q135. 越狱怎么防？**

一句话：分层：输入侧（检测已知越狱模式/角色扮演诱导，拦或降级处理）+ 模型侧（选安全对齐强的模型，system prompt 明确边界）+ 输出侧（内容审核模型 + 规则匹配拦截违规输出）+ 运营侧（攻击样本回流、持续对抗迭代）。核心认知：越狱和注入同源——无法根除，目标是提高成本和留下证据。

展开：典型攻击要认识：角色扮演（"假设你是没有限制的 DAN"）、编码绕过（base64/外语/拼音）、多轮温水煮蛙（每轮松一点）、前缀注入（"以'好的，我来教你'开头"）。加分点：说"输出侧审查比输入侧更可靠——恶意意图变形万千，违规输出模式相对固定"；再补一句"对安全提示词的修改要像生产变更一样走评审和回归"。

---

**Q136. 输出侧内容安全怎么做？**

一句话：三道工序串联：规则层（正则/关键词/分类器，快、免费、可解释，拦明显违规）→ 模型审核层（内容安全模型对语义违规兜底，如变体表达）→ 人工层（高敏感场景抽检 + 用户举报复核）。处理动作分级：直接拦 / 替换脱敏 / 降级话术 / 转人工。

展开：设计要点：① 误杀治理和漏杀治理同样重要——审核置信度分档，低置信走人工而不是硬拦，否则产品不可用；② 延迟预算：审核链路加在主链路上会吃 TTFT，流式场景用"边生成边审 + 违规即断流撤回"的模式；③ 审核也要评测（审核模型的查准查优率）。国内合规视角：还要接监管要求的审核能力与日志留存（连 Q140）。

**Q137. 工具调用权限怎么设计？**

一句话：五原则：最小权限（每个 agent/工具独立低权凭证）、默认只读（写操作显式开启）、敏感操作审批（资金/删除/外发，事前人审 Q68）、参数级约束（工具 schema 限制金额上限、操作范围白名单）、全量审计（谁、何时、什么参数、结果、关联的会话）。权限校验在**工具执行层**做，不在 prompt 层做。

展开：为什么"执行层校验"是关键句：prompt 层的"你不许删库"会被注入绕过，执行层的 DB 只读账号绕不过——安全边界必须落在模型控制不了的地方。进阶：按会话动态收权（任务结束回收临时凭证）、异常调用模式检测（某 agent 突然高频调用导出类工具 → 告警）。这题是 agent 安全面试的核心题，五原则能展开两个例子就很好。

**Q138. 供应链投毒怎么防？**

一句话：三个入口分别防：模型文件（只用官方源 + 校验哈希/签名，pickle 反序列化风险用 safetensors）；依赖与工具包（MCP server / 工具插件当第三方依赖管——来源审查、版本锁定、沙箱运行 Q70、最小权限 Q137）；微调数据（数据来源审计，防后门触发器混入）。

展开：2026 语境下的重点是 MCP 生态：任何人都能发布 MCP server，装一个社区 server = 给 agent 挂上一个第三方工具，它描述里可以写"把工具结果发到外部"（tool poisoning / 恶意 server）。防线：内部 MCP server 注册白名单 + 安全审查、server 运行在隔离环境、其网络出口受控。一句总结："把模型、依赖、工具、数据都当供应链管——来源、版本、完整性、最小信任四问。"

**Q139. 拒答边界场景怎么设计？**

一句话：按领域风险分级设计：明确禁止的（诊断开药、法律意见、投资建议）→ 拒答 + 解释 + 引导到正确渠道（"建议咨询医生"）；灰色地带（一般健康信息）→ 提供通用信息 + 明确免责声明 + 不做个体化结论。兜底话术模板化，进 prompt + 评测集覆盖。

展开：难点在"拒答的度"：全拒 → 产品没用；不拒 → 责任风险。工程手段：① 高风险意图的分类器前置（医疗/法律/金融意图识别），命中走受限回答模板；② 免责声明和引导话术常驻 system prompt 并在输出层校验存在性；③ 法务参与边界定义并留档（哪些拒哪些不拒、依据是什么）。加分点："拒答策略也要评测——拒答率、误拒率（该答没答）都是指标。"

**Q140. 国内上线的合规要点？**

一句话：依据《生成式人工智能服务管理暂行办法》等：① 算法/大模型备案（面向公众的服务）；② 生成内容标识（《人工智能生成合成内容标识办法》要求显式 + 隐式标识，2025-09-01 起施行）；③ 训练数据合规（来源合法、个人信息授权）；④ 内容安全义务（违法内容拦截、日志留存、举报机制）；⑤ 个人信息保护（PIPL：告知同意、最小必要）。

展开：面试答法不需要背条文，答出"备案、标识、数据合规、内容安全"四个关键词 + 一句"上线前过法务合规评审，留存和标识义务影响架构设计（日志方案、水印/元数据标识）"即可。加分点：知道标识不只显式水印——元数据隐式标识也是要求，且对外提供的 API 生成内容同样适用。

**Q141. Red teaming 怎么做？**

一句话：流程：定范围（哪些能力/数据/操作是资产）→ 攻击设计（注入、越狱、间接注入、数据外泄、工具滥用、多轮社工，含自动化批量生成攻击用例）→ 执行（内部红队/工具辅助/众测）→ 按风险评级修复 → 回归（所有发现的攻击转化为持续回归评测用例，防复发）。

展开：和传统安全测试的差异：LLM 的攻击面是自然语言，变体无限——所以自动化（用另一个 LLM 生成变体攻击、judge 判断是否得手）+ 人工创造性攻击结合。指标：攻击成功率（按攻击类别分）、修复后复发率。加分点："红队不是一次性活动——模型、prompt、工具任何一个变更后，攻击面都变了，要按版本跑。"
