# 七、微调与训练（参考答案）

---

**Q110.【P0】 SFT 完整流程？数据格式？**
一句话：流程：定目标（想让模型改什么行为）→ 造数据（指令-回答对，质量>数量）→ 切 train/val → 训练（LoRA 起步，监控 val loss）→ 评测对比基座 → 部署。格式：chat 模板的多轮消息（system/user/assistant），或带 loss mask——只对 assistant 回答部分算 loss，不学用户输入。

展开：

**流程拆成六步，每步要做什么：**

1. **定目标**：先写清楚"基座哪里不行"。可验证的目标如"客服回复必须先致歉再给方案、不超过 200 字"，而不是"让模型更聪明"（那是预训练的事，微调做不到）。
2. **造数据**：每条 = 一个输入 + 一个理想回答。几百条高质量的起步（见 Q115）。
3. **切 train/val**：留 10~20% 做验证集，且训练前冻结，用于判断是否过拟合（见 Q117）。
4. **训练**：LoRA 起步（便宜、够用，见 Q111），盯着验证 loss——它回升就停。
5. **评测**：微调版 vs 基座版在业务评测集上对比，别只看训练 loss 好看。
6. **部署**：打版本 tag、灰度放量、留好回滚（见 Q119）。

**数据格式**（LoRA 微调开源模型常用 Alpaca/ShareGPT 格式）：
```json
{"messages": [
  {"role": "system", "content": "你是差旅客服…"},
  {"role": "user", "content": "发票丢了怎么报销"},
  {"role": "assistant", "content": "分三种情况：…"}
]}
```
训练时整段对话拼成一个序列喂进去，但 loss mask 会把 system 和 user 部分挡住——**模型只为 assistant 回答的每个 token 计算 loss**。类比：学生做阅读理解，文章是给的不是让他背的，只有答案部分才算分。

被追问最多的点：① 数据规模——行为对齐几百到几千条高质量样本常有感，知识灌注需要海量（那不如 RAG）；② loss mask 不做 → 模型在学习"生成用户的问题"，浪费容量。

**Q111.【P0】 LoRA 原理？r/alpha？何时全参？**
一句话：冻结原权重 W，训练一个低秩增量 ΔW = B·A（A 降维、B 升维，秩 r ≪ d）——可训练参数从几十亿降到几百万~几千万，显存暴省，效果对行为类任务接近全参。r（秩，容量）常见 8~64；alpha（缩放系数）控制增量的"力度"，实际影响的是 alpha/r 的比值，加大 alpha ≈ 学得更激进。

展开：

**LoRA 解决什么问题**：全参微调一个 7B 模型，权重、梯度、优化器状态加起来要几十 GB 显存，普通团队玩不起。LoRA 的观察是：**微调时权重的变化量 ΔW 其实是低秩的**——一个任务要学的新"知识"信息量有限，不需要动全部 70 亿个参数。类比：把一本书改第三版，不需要重写整本书，只需要一份"修订批注"；LoRA 训练的就是这份批注。

**机制分步**：

1. 原始权重 W（d×d，如 4096×4096）**完全冻结**，不参与梯度更新；
2. 旁边加两个小矩阵：A（r×d，把 4096 维压到 r 维，如 r=16）和 B（d×r，再升回 4096 维）；
3. 前向计算变成 `h = Wx + (B·A)x`——原始输出 + 增量输出；
4. 只训练 A 和 B：参数量从 4096×4096≈1678 万 降到 2×4096×16≈13 万，缩 100 多倍；
5. 推理时可以把 B·A **合并回 W**，结构与原模型完全一样，零额外推理开销。

**r 和 alpha 到底调什么**：r 是"批注写多厚"——容量上限，太小学不动复杂任务，太大失去省显存意义，16 是常用起点；alpha 是"批注的音量"——增量输出乘以 alpha/r，r 翻倍时把 alpha 也翻倍可保持力度不变。所以实践口诀：**先固定 alpha=2r，只扫 r**。

**何时全参**：数据量大（10 万+）、任务和预训练分布差异大（领域 continue pretrain）、LoRA 扫参确实到不了标——代价是显存和算力数倍起。这题必须讲出"ΔW=B·A"这个式子。

**Q112.【P1】 QLoRA 是什么？什么时候用？**
一句话：QLoRA = 把冻结的基座量化到 4bit（NF4）再挂 LoRA 训练——基座显存占用降约 4 倍，让单张 24G 消费级/工作站卡能微调 30B+ 模型。用在：预算/显存紧张、试错阶段的快速实验；代价：训练更慢、效果比全精度 LoRA 略降（通常可接受）。

展开：

**它和 LoRA 的关系**：LoRA 冻结基座只训小矩阵，但冻结的基座本身还是要占显存——7B 模型 bf16 要 14G，70B 要 140G。QLoRA 的想法很直接：基座反正不动，**存成 4bit 就行**，只在计算时临时反量化。

**三个关键词**：

1. **NF4**：一种 4bit 数值格式。普通 int4 均匀切分数轴，但模型权重服从正态分布（大部分挤在 0 附近），NF4 按正态分布的分位点切分，同样 4bit 精度损失更小；
2. **双重量化**：量化本身需要存"每块的缩放常数"，把这些常数再量化一次，再省约 0.4 bit/参数；
3. **paged optimizer**：优化器状态显存不够时借用 CPU 内存，平滑显存峰值，防 OOM。

**数字感受一下**：70B 模型，bf16 基座 ≈ 140G；4bit 基座 ≈ 35G + 十几 GB 的 LoRA 训练开销 → 一台 48G 的卡能跑。

面试官爱问"QLoRA 量化的基座会影响最终效果吗"——量化的是冻结基座，LoRA 增量仍以 bf16 训练；推理时可合并或保持量化，效果损失主要来自 4bit 基座本身，实践中对中小任务影响小。

**Q113.【P1】 RLHF vs DPO？**
一句话：RLHF：训奖励模型 + PPO 强化学习优化，效果上限高但工程重（四个模型同时在显存里、训练不稳、超参敏感）；DPO：直接从"偏好对（chosen/rejected）"优化策略，绕过奖励模型和 RL 循环，简单稳定像 SFT 一样训——资源有限的团队首选，因此流行。

展开：

**先补背景——两者都在解决同一个问题**：SFT 只教了模型"好回答长什么样"（模仿范例），没教"坏回答有多坏"。对齐要的是拉开放好和放坏的距离，两者的原料都是**偏好数据**：同一个问题，人标注出 chosen（更好的回答）和 rejected（更差的回答）。

**RLHF 的三步走（经典 OpenAI 路线）**：

1. 收集人类排序数据，训一个**奖励模型**（Reward Model）——它给任何回答打分，分数代表"人类会有多喜欢"；
2. 用 PPO 让策略模型生成回答、奖励模型打分、按分更新策略——像训练小狗：做对给零食，模型学着朝高分方向走；
3. 同时要一个 KL 惩罚把模型拴在原模型附近，防止它钻奖励模型的空子（reward hacking）。

**为什么工程重**：显存里要同时装 4 个模型（策略、奖励、参考、价值），PPO 超参极敏感，训练常崩。

**DPO 的巧思**：数学上可以证明"奖励"和"策略"之间有解析关系，于是可以把奖励模型**折叠进损失函数**——直接拿偏好对算一个类似分类的损失（拉大 chosen 和 rejected 的对数概率差），梯度直传，像训 SFT 一样稳定。类比：RLHF 是"先培训一位裁判再让小狗对着裁判学"，DPO 是"把裁判的判断标准直接写进教学大纲"。

**选型**：有强 RL 基建和大预算 → RLHF/PPO 仍是最优上限；大多数应用团队 → DPO/KTO（数据是二元好/坏标注时 KTO 更省，不需要成对）。加分点：知道两者都用"偏好数据"，数据质量同样是天花板——标注分歧大的偏好对是毒数据。

**Q114.【P0】 prompt / RAG / 微调决策树？**
一句话：依次问：① prompt + few-shot 能解决吗？（最先试，几乎零成本）② 缺的是事实知识吗？→ RAG（可更新、可溯源）；③ 是行为/格式/风格不对，且 prompt 拉不动？→ 微调；④ 又缺知识又缺行为？→ 微调 + RAG 叠加。成本量级：prompt ≈ 0；RAG = 检索系统建设 + 每次查询的检索开销；微调 = 数据标注 + 训练 + 持续维护版本，最贵且知识会过期。

展开：

**为什么按这个顺序**：成本和风险递增。prompt 改一句话就能回滚；RAG 要建检索系统但知识随时可更新；微调动了模型权重，从数据标注到版本维护都是持续投入。先便宜的，每层挡不住再升级。

**核心判据一句话**：**知识会过期，行为不会。** 缺事实/知识（文档、政策、产品信息）→ 永远选 RAG，因为知识天天变、还要溯源；缺行为（语气、格式、流程稳定性）且 prompt 拉不动 → 微调，因为行为相对稳定不过期。

一个反例常被追问："让模型学会我们公司的产品文档"该微调吗？——不该：文档天天更新，微调版永远滞后还无法溯源，RAG。反过来："让模型始终用我们品牌的语气、按固定工单格式输出"——prompt 试了不稳定、量大管不住 → 微调合适（行为稳定不过期）。

**Q115.【P0】 微调数据从哪来？质量 vs 数量？**
一句话：来源四路：人工撰写（贵但准，用于种子和规范）、业务日志提炼（真实分布，需清洗脱敏）、强模型蒸馏合成（便宜量大，需人工抽检校准）、开源数据集（打底通用能力）。几百~几千条高质量数据足以改变行为模式；上低质万条不如精修千条——错误的示范会被忠实学习，垃圾进垃圾出。

展开：

**为什么质量碾压数量**：SFT 是模仿学习——数据里每个错误（事实错、格式乱、风格飘）都会被模型忠实学走，它没有"去其糟粕"的能力。而改变**行为模式**（语气、格式、流程）需要的是清晰的示范，不是海量重复，所以几百条够用；改变**知识**才需要海量数据，而那本来就该用 RAG（见 Q114）。

**质量三判据**：

1. **多样性**：覆盖输入的真实分布和边界 case——全是很规整的问题训出来，遇到口语、错别字就崩；
2. **一致性**：同场景的回答风格统一——三个人各写各的，模型学成四不像；
3. **正确性**：事实错误直接教坏，且很难在后续训练里扳回来。

实操配比：先用 500 条试水验证管线通、效果方向对，再扩量。加分点：说"数据质量评测也是评测——先抽检数据再训练，比训练完才发现问题便宜得多"。

**Q116.【P1】 灾难性遗忘是什么？怎么防？**
一句话：微调把模型拉向新任务分布时，原有通用能力（对话、常识、推理）被"覆盖"式遗忘。防线：① 混入通用数据回放（replay，如混 10~30% 通用指令数据）；② LoRA 本身就是隔离（增量不改原权重，遗忘天然轻）；③ 小学习率 + 少 epoch，别把模型拧太狠；④ 评测必须含通用能力回归集。

展开：

**为什么会遗忘**：模型的所有能力都存在同一份权重里，没有"分区"。微调的梯度只来自新任务数据，权重整体朝新分布挪动，途中原有能力依赖的那些"参数组合"就被破坏了——像在一个共享硬盘上反复覆写新文件，旧文件没删但数据被覆盖了。

**事故样例**：用客服工单数据微调后，模型变得只会输出工单格式，正常聊天也往工单套——这就是拧过头了。

**四道防线怎么理解**：

1. **replay**：训练数据里混通用指令数据，相当于边学新课边复习旧课，梯度里始终有保护旧能力的成分；
2. **LoRA**：原权重一个字节不动，"遗忘"最多发生在小增量矩阵里，天然比全参轻一个量级——这是 LoRA 流行的重要原因；
3. **低 lr + 少 epoch**：挪得越少，破坏越小；
4. **回归评测**：没有度量就没法防，见 Q117 的通用回归集。

诊断：训练前建一套"通用能力哨兵集"（常识问答、写作、数学各若干条），训练后跑，回退明显即过拟合或遗忘。工程心法："微调是手术不是重塑——切口越小（LoRA + 低 lr），恢复越快。"

**Q117.【P0】 怎么证明微调有效？含过拟合判断？**
一句话：三组对照评测：基座 vs 基座+prompt vs 微调版，在你的**业务评测集**（不在训练集里！）上比目标能力，同时在**通用回归集**上确保没退化；判过拟合：训练 loss 持续降但验证 loss 回升、或训练数据原句复述（背题）、或对训练分布外的输入崩坏——出现任一即停止/回退到更早 checkpoint。

展开：

**为什么要三组对照**：只有一组"微调版好不好"说明不了问题。加"基座"才知道微调带来了多少提升；加"基座+prompt"才知道这提升是不是随便写写 prompt 也能拿到——很多微调收益其实是精心 prompt 就能追平的，这笔钱可以省。

**过拟合三信号怎么读**：

1. **验证 loss 回升**：训练 loss 是"做课后习题的正确率"，验证 loss 是"做新题的正确率"。前者降后者升 = 背题没学会，经典教科书式过拟合；
2. **原句复述**：问模型一个训练集里的问题，它一字不差吐回训练答案——在"背"不在"学"；
3. **分布外崩坏**：训练数据是规整工单，用户换个口语问法就胡言乱语——学到的模式太窄。

**"自欺欺人"的常见姿势（要主动避雷）**：① 用训练数据评测（肯定好，无意义）；② 评测集和训练数据同源（同一批人写的，风格泄漏）；③ 只报目标指标不报退化指标（学会了一件事忘了十件事）。正确姿势：评测集来自真实用户请求抽样，训练前就冻结。一句话总结："微调报告必须有两列：目标能力涨了多少，通用能力掉了多少。"

**Q118.【P2】 DeepSeek-R1 训练流程？应用侧启发？**
一句话：大致流程：基座 → R1-Zero 式纯 RL（可验证奖励：数学/代码对错直接给信号，模型自发长出推理链）→ 冷启动 SFT（整理高质量长推理数据）→ 多轮 SFT + RL 交替（推理 RL + 通用对齐 RL）→ 蒸馏到小模型（用 R1 生成推理数据 SFT 小模型）。应用侧启发：① 可验证任务（代码、数学）用推理模型收益最大；② 强模型的推理输出可以蒸馏给小模型（数据是免费的）；③ "测试时多想"（long CoT）是和"堆参数"正交的能力轴。

展开：

**流程按叙事顺序拆**：

1. **R1-Zero：纯 RL 起步**。不给任何推理示范，只用"可验证奖励"训练——数学题答案对不对、代码过不过测试，机器能自动判对错，不需要人标。惊人发现：模型为了拿高分**自发长出了反思、验算、换思路**等推理行为（涌现，没人教）。但可读性差、中英混杂；
2. **冷启动 SFT**：整理少量高质量、格式规整的长推理数据做 SFT，解决可读性问题；
3. **SFT + RL 交替迭代**：推理数据越滚越多，推理 RL 和通用对齐 RL 分开做，反复几轮；
4. **蒸馏**：用最终 R1 生成 80 万条推理数据，直接 SFT 给 Qwen/Llama 小模型——小模型没做一步 RL 就学会了推理，说明**蒸馏比小模型自己跑 RL 便宜有效得多**。

**应用侧为什么重要**：这题 2025-2026 高频，考的是你是否跟得上前沿叙事，重点在**启发**部分而不是复述论文细节。三个启发对应三类决策：什么任务值得上推理模型（可验证的）、便宜提升小模型的路（蒸馏数据）、以及能力提升的新维度（同一模型多给思考 token 也能涨点，不一定换大模型）。能说出"RLVR（可验证奖励的 RL）让推理能力涌现"和"蒸馏数据让小模型也能推理"两个点就达标。

**Q119.【P1】 微调模型的部署与版本管理？**
一句话：像管理代码版本一样管理模型：训练任务记录（数据版本 + 超参 + 基座版本 + 评测报告）→ 产物（LoRA 权重）打版本 tag 入模型仓库 → 部署时基座 + LoRA 组合加载（多适配器热切换，一个基座服务多个 LoRA）→ 灰度放量 → 出问题秒级切回旧 tag。回滚 = 流量切回旧适配器，不需要重训。

展开：

**为什么这题值得单独问**：模型和代码一样会出事故，区别是模型事故往往更隐蔽（效果慢慢变差而不是报错），所以版本管理的核心是**可追溯 + 可回滚**。

**关键链路五环**：

1. **训练可追溯**：每次训练记录"哪版数据 + 哪套超参 + 哪个基座"，否则三个月后没人能回答"线上这个模型是怎么来的"；
2. **产物版本化**：LoRA 权重打 tag 入模型仓库，评测报告随 artifact 存档——每个版本带"体检报告"；
3. **组合加载**：基座部署一次，多个任务适配器像配置一样热切换——客服 LoRA、销售 LoRA 共用一个基座服务；
4. **灰度**：新 LoRA 先放 5% 流量，看评测指标和业务指标；
5. **回滚**：LoRA 的运维优势在这里兑现——出问题把流量切回旧适配器即可，秒级，不需要重训。

数据集也要版本化（DVC/对象存储 + manifest），否则"这个模型是用哪版数据训的"无法回答。merged 版（把 LoRA 合并进基座的完整权重）用于追求极致推理性能的场景，但牺牲了热切换。
