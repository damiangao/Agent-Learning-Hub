# 一、LLM 基础（参考答案）

> 格式：**一句话答案** → **展开（帮你理解）** → **陷阱/加分点**

---

**Q1. Transformer 核心组件；Q、K、V 是什么？**

一句话：核心是 Self-Attention + 前馈网络（FFN），堆 N 层，配合残差连接、LayerNorm、位置编码。Q/K/V 是每个 token 的三种"视角"。

展开：把 Self-Attention 想成图书馆查资料：每个词生成一个**查询向量 Q**（我想找什么）、一个**键向量 K**（我是什么样的一张索引卡）、一个**值向量 V**（我实际携带的信息）。Q 和所有 K 做点积算相关度 → softmax 成权重 → 加权求和所有 V。结果就是"这个词的新表示，融合了它最相关的上下文词"。公式 `Attention(Q,K,V)=softmax(QKᵀ/√d)V`，除以 √d 是防止点积过大导致 softmax 梯度消失。

陷阱：能写出公式只是及格线；加分点是说得出 FFN 占了大部分参数、Attention 负责"信息路由"，以及多头机制（多个 Q/K/V 投影）让模型同时关注不同类型的关系（语法/语义/指代）。

---

**Q2. 为什么主流 LLM 都是 Decoder-only？**

一句话：Decoder-only 用因果注意力做"预测下一个词"，训练目标与生成任务天然一致，且架构简单、可大规模并行训练。

展开：Encoder-only（BERT）看全文双向上下文，擅长理解（分类、检索）；Encoder-Decoder（T5）适合明确的输入→输出转换（翻译）；Decoder-only（GPT 系）自回归生成。胜出的工程原因：① 训练目标（next token prediction）不需要人工标注，能吃全互联网；② 因果 mask 让每个位置只看左边，序列内所有位置的预测可以**一次并行计算**，训练效率高；③ scaling law 下简单架构 + 大数据 + 大参数持续涨点，没有换架构的理由。

陷阱：别只说"因为 GPT 用它"。加分点：提 KV cache 使 Decoder-only 推理时每个新 token 只算一步、Prefix 复用友好，这也是工程上它占优的原因。

---

**Q3. BPE 原理；为什么中文 token 更贵？**

一句话：BPE 从字符开始，迭代把最高频的相邻符号对合并成新 token，直到词表达到目标大小。中文贵是因为常用字在词表中常被拆成单字甚至字节，同样语义需要更多 token。

展开：训练时统计语料中相邻 token 对的频率，把最频繁的一对合并（如 `t`+`h`→`th`），重复几千到几万次。效果是高频词（英文 "the"）一个 token，低频词被拆成子词。主流词表以英文语料为主训练，一个英文单词约 1.3 token，而一个常用汉字常需 1~2 token，且不表意的偏旁/字节也会单独成 token——同样一篇 1000 字的文章，中文 token 数往往是英文同等内容的 1.5~2 倍。

陷阱：说清影响——成本、上下文窗口有效容量、生成速度都按 token 计。加分点：知道词表大小（如 10 万级）和 byte-level BPE（保证任何输入都能编码）。

---

**Q4. 上下文窗口是什么？超长文档怎么办？**

一句话：上下文窗口是模型一次能"看到"的最大 token 数（含输入+输出），超长文档要靠检索（RAG）、分块处理（map-reduce）、或上下文压缩。

展开：窗口外的内容模型完全不知道，不是"记住一部分"。处理手段按优先级：① **RAG**——只把相关片段放进窗口（生产首选）；② **分层摘要/map-reduce**——每块先摘要再汇总；③ **滑动窗口+增量处理**；④ 换长上下文模型（但注意长窗口≠长窗口内性能好，中间信息会被忽略，见 Q26）。

陷阱：面试官爱追问"窗口 128k 是不是就能直接塞一本书？"——要答：能塞但效果会掉（lost in the middle）、成本按 token 涨、延迟变长，生产上 RAG 通常又便宜又准。

**Q5. temperature / top_p / top_k 控制什么？**

一句话：三者都控制采样的随机性。temperature 按"浓度"缩放整个概率分布，top_k 只保留概率最高的 k 个词，top_p 只保留累计概率达 p 的最小词集（nucleus sampling）。

展开：模型每步输出一个全词表的概率分布。temperature→0 每次都选最高概率词（贪心，稳定可复现）；调高则低概率词机会变大（多样、有创意，但易跑偏）。top_k=50 意味着只在 50 个候选里采样。top_p=0.9 更自适应：候选词数量随分布尖/平自动变化。

实践默认：问答/结构化输出 `temperature=0~0.3`（要稳定）；文案创作 0.7~1.0；代码生成 0~0.2。陷阱：temperature 和 top_p 别同时大幅调；判断题考"temperature 越低越有创意"——反了。

**Q6. 幻觉为什么会产生？**

一句话：根因是 LLM 的训练目标是"预测最像样的下一个词"，不是"输出真实"——它是个概率补全器，遇到知识空缺时会生成统计上流畅但事实上错误的内容，且无法自己区分知道与不知道。

展开：三层原因：① 训练目标不奖励事实性，流畅即合理；② 知识有截止日期、长尾知识覆盖稀疏；③ 解码采样本身有随机性。诱发因素：提问里含错误预设（模型顺着编）、要求引用不存在的东西、知识边界外的问题。生产缓解：RAG（给它资料）、允许说"不知道"（prompt + 微调）、引用溯源、生成后校验（见 Q113）。

加分点：说出"幻觉无法根除，只能通过架构和流程把概率压低 + 影响限制住"这种工程视角，比背成因更加分。

**Q7. Embedding 是什么？为什么用余弦相似度？**

一句话：Embedding 把文本映射成高维向量，语义相近的文本向量方向相近；余弦相似度只比较方向不比较长度，更适合比较语义。

展开：训练目标通常是"让语义相近的句子在向量空间中靠近"。余弦相似度 = 夹角余弦，范围 [-1,1]，归一化后与向量的绝对大小无关——而文本长度、词频会影响向量模长，语义不该受此影响。（工程上很多向量库会先归一化，此时内积=余弦，用内积是为了算得快。）

陷阱：能说出典型维度（768/1024/1536/3072）和"embedding 模型也是 Transformer，把整段文本池化成一个向量"。

**Q8. 一次调用的成本和延迟由什么决定？**

一句话：成本 ≈ 输入 token 单价 × 输入量 + 输出 token 单价 × 输出量（输出单价通常是输入的数倍）；延迟 ≈ 排队 + prefill（处理输入）+ 逐 token 解码时间。

展开：**输出 token 更贵**（有的贵 3~5 倍），因为解码是逐 token 自回归、每步都要读写全部 KV cache，算力访存都贵；输入是一次性并行 prefill，便宜且快。所以优化优先砍：① 输出长度（限制 max_tokens、要求简洁）；② 重复输入（prompt cache）；③ 模型档位。延迟核心指标：TTFT（首 token 时间）和每 token 输出速度（吐字速度），用户感知主要由 TTFT + 总输出长度决定。

**Q9. 预训练 → SFT → RLHF 各解决什么？**

一句话：预训练学语言和世界知识（完形填空式），SFT 学"听懂指令、按格式回答"，RLHF/DPO 学"哪种回答人类更喜欢"（对齐）。

展开：预训练用海量无标注文本做 next token prediction，产出的是一个"会说话但不听指挥"的基座——问它问题它可能继续编更多问题。SFT 用几万~百万条"指令→高质量回答"对做监督微调，教会指令跟随和格式。RLHF：人类对多个回答排序 → 训练奖励模型 → 用 RL（PPO）最大化奖励；DPO 是简化版，直接用偏好对训练，不需要单独的奖励模型和 RL 循环（详见 Q95）。

---

**Q10. repetition_penalty 和 logit_bias 干什么的？**

一句话：repetition_penalty 惩罚已出现过的 token 降低其概率，防止复读机；logit_bias 直接给指定 token 的 logits 加/减一个偏置，硬性提高或禁止某些词。

展开：复读是解码采样在高 temperature 之外的另一类失败——模型对刚输出过的词概率仍高。repetition_penalty（常见 1.0~1.2）按"已出现次数"打折。logit_bias 的典型用途：禁止模型输出某词（bias=-100 基本封死）、强制输出格式词。注意两者都不要过度：惩罚太强会伤语法（"的的"变乱造词）。

**Q11. 给业务场景怎么选模型？**

一句话：按"任务难度 × 数据敏感性 × 预算 × 延迟要求"四维决策，先便宜的，跑评测，不达标再升级。

展开：决策顺序：① 数据能出内网吗？不能 → 私有化开源（Qwen/DeepSeek 系）；② 简单任务（分类、抽取、格式转换）→ 小模型/便宜模型，省钱且快；③ 复杂推理/Agent → 旗舰模型或推理模型；④ 有候选名单后，**用自己业务的评测集跑分**（Q109），不迷信公开榜单。再叠加考虑：上下文长度需求、是否要多模态、生态（function calling 支持质量）。

陷阱：只报模型名不给决策框架是减分的；加分点：说"先建评测集再选模型"以及"大小模型路由省钱"。

**Q12. MoE 原理？为什么便宜？**

一句话：MoE 把 FFN 层换成多个"专家"子网络，每个 token 只被路由到其中 1~2 个专家计算——总参数量大，但每个 token 的实际计算量小，所以推理便宜。

展开：门控网络（router）为每个 token 选 top-k 专家，只有被选中的专家参与前向计算。比如 671B 总参数的 DeepSeek-V3，每 token 激活约 37B。代价：所有专家都要装进显存（显存需求大）、路由负载不均要处理、多机部署时专家分布影响通信。

陷阱：澄清"便宜的是计算不是显存"，MoE 服务化部署门槛比稠密模型高。

---

**Q13. RoPE 是什么？为什么容易外推长度？**

一句话：RoPE（旋转位置编码）通过对 Q/K 向量按位置旋转特定角度来注入相对位置信息，注意力得分只依赖相对距离，且可以外推/插值到训练长度之外。

展开：把 Q、K 的每两维当成平面上的点，按其位置 m 旋转 m·θ 角度。两个 token 做点积时，结果只与它们的**相对位置差**有关（类似复数乘法的辐角相减）。好处：无额外参数、天然表达相对位置。长度外推手段（NTK-aware scaling、YaRN 等）本质是调整旋转角的频率，让训练时的"单位刻度"拉伸覆盖更长序列。

P2 题，能说清"用旋转编码相对位置、可通过频率缩放外推"即可。

---

**Q14. 多模态模型怎么"看"图像？**

一句话：图像经视觉编码器（如 ViT）切成 patch 编码成向量序列，经投影层映射到与文本 token 同一空间，当作"图像 token"拼进上下文一起喂给 LLM。

展开：主流方案 = 视觉编码器 + 连接层 + LLM 三件套。LLM 本身不认识像素，它只是把图像 token 当作普通输入 token 做注意力——所以模型能"引用"图中内容但机制上仍是 token 序列上的补全。要点：一张图通常占几百~几千 token（这就是图片输入贵的原因）；视频 = 多帧。

---

**Q15. 推理模型的 reasoning token 是什么？什么时候用？**

一句话：推理模型（o1/R1 类）在正式回答前先生成一段"思考"token（思维链），这些 token 同样计费同样耗时，换来在数学/代码/复杂推理上的显著提升。

展开：这类模型通过 RL 训练出"先推理再作答"的行为，思考过程可能几千 token。成本影响：输出 token 数翻几倍 → 延迟和费用大增。适用判断：多步推理、数学、复杂 debug 用它；简单分类、抽取、格式转换**不要用**——纯浪费钱和时间。加分点：知道可以限制思考预算（如 reasoning_effort 参数）做成本/效果权衡。
