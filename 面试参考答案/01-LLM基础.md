# 一、LLM 基础（参考答案）

> 格式：**一句话答案** → **展开（帮你理解）** → **陷阱/加分点**

---

**Q1. Transformer 核心组件；Q、K、V 是什么？**

一句话：核心是 Self-Attention + 前馈网络（FFN），堆 N 层，配合残差连接、LayerNorm、位置编码。Q/K/V 是**同一个词向量乘三个不同权重矩阵**得到的三种角色：Q（Query 查询）=我要找什么；K（Key 键）=我如何被匹配到；V（Value 值）=我实际携带的信息。

展开：

先建立直觉——像搜索引擎：

| 角色 | 类比 | 回答的问题 |
|---|---|---|
| **Q** | 你输入的搜索词 | 我在找什么？ |
| **K** | 每个网页的标题/关键词 | 我能被怎样搜到？ |
| **V** | 网页的正文内容 | 匹配后真正带走的信息 |

区别在：搜索引擎只返回最匹配的一条（硬匹配），Attention 是**软匹配**——按相关度给所有词分配权重，加权混合所有人的 V。

为什么拆成三个矩阵？同一个词向量 `x` 分别乘 `W_Q`、`W_K`、`W_V` 得到三种角色，因为**"如何被匹配到"和"匹配到之后给什么"是两件独立的事**。比如"The cat sat on the mat because it was tired"里，"it" 要找到 "cat"——匹配靠指代关系（Q/K 的事），拿到手的是猫的全部语义信息（V 的事）。若直接用 `x` 同时当 K 和 V，这两件事就绑死了。三个矩阵都是训练学出来的，模型自己学会"该用什么特征去匹配"。

公式四步走（句子有 n 个词），`Attention(Q,K,V)=softmax(QKᵀ/√d_k)V`：

1. `Q @ Kᵀ` → n×n 相关度分数矩阵；第 i 行 j 列 = 词 i 对词 j 的关注度原始分；
2. `÷ √d_k` → 维度越大点积天然越大，不除的话 softmax 会"一家独大"，梯度消失；
3. `softmax`（按行）→ 每行归一化成权重、和为 1，即"这个词把注意力怎么分配给全句"；
4. `@ V` → 按权重加权混合所有词的 V，得到融合了上下文的新表示。

接着上面的例子："it" 的 Q 在问"我在指代谁"，"cat" 的 K 在说"我是动物名词、可被指代"，二者点积得分高 → softmax 后 "cat" 权重最大 → "it" 的输出 ≈ 以 cat 的 V 为主的加权混合，模型就此"知道" it 指猫。

多头：一组 Q/K/V 只能关注一种关系（比如只看指代），所以并排跑 8~16 组，每组有自己的 W_Q/W_K/W_V，各关注不同关系（指代/语法/语义……），输出拼起来再线性变换一次，即 Multi-Head Attention。

陷阱：能写出公式只是及格线；最常见的两个卡点要主动讲清——① Q/K/V 是同一个输入向量的三种投影，不是三种不同输入；② 公式四步对应"搜索→打分→归一化→加权取货"这个流程。加分点：FFN 占了大部分参数、Attention 负责"信息路由"。

**Q2. 为什么主流 LLM 都是 Decoder-only？**

一句话：Decoder-only 用因果注意力做"预测下一个词"，训练目标与生成任务天然一致，且架构简单、可大规模并行训练。

展开：先分清三种架构的区别——

| 架构 | 代表 | 注意力方向 | 擅长 |
|---|---|---|---|
| Encoder-only | BERT | 双向，每个词看全文 | 理解类任务（分类、检索） |
| Encoder-Decoder | T5 | 编码器双向 + 解码器自回归 | 明确的输入→输出转换（翻译、摘要） |
| Decoder-only | GPT 系 | 因果，每个词只看左边 | 自回归生成 |

直觉：Encoder 像读完一整段再下结论，Decoder 像一边写一边读自己已写的内容。主流 LLM 选了后者，工程原因有三：

1. **训练数据免费**：next token prediction 不需要人工标注——任何文本都能自己造题（把下一个词遮住当答案），所以能吃全互联网；BERT 的 MLM 也自监督，但 Encoder-Decoder 需要设计输入→输出结构的语料，更麻烦。
2. **训练能并行**：因果 mask 下，序列里每个位置都只看左边、预测下一个词，1000 个位置的预测可以**一次矩阵运算全算出来**，不用真的"一个词一个词生成"。训练效率高。
3. **scaling law 兜底**：简单架构 + 大数据 + 大参数被证明持续涨点，没有理由为一个不更差的架构冒工程风险。

陷阱：别只说"因为 GPT 用它"——面试官想听的是上面 2、3 条"为什么 GPT 能赢"。加分点：提 KV cache 使 Decoder-only 推理时每个新 token 只算一步、Prefix 复用友好，这也是工程上它占优的原因。

**Q3. BPE 原理；为什么中文 token 更贵？**

一句话：BPE 从字符开始，迭代把最高频的相邻符号对合并成新 token，直到词表达到目标大小。中文贵是因为常用字在词表中常被拆成单字甚至字节，同样语义需要更多 token。

展开：BPE（Byte Pair Encoding）像"玩拼词游戏"：

1. 先把语料全部拆成最小单位（字符或字节），此时每个词都是一长串碎片；
2. 统计**哪两个相邻符号总是结对出现**，把最频繁的一对合并成新符号（如 `t`+`h`→`th`，下次 `th`+`e`→`the`）；
3. 重复第 2 步几千到几万次，直到词表达到目标大小（主流是 10 万级）。

效果：高频词被合并成单个 token（"the" 一个 token），低频词保留在子词粒度（"tokenization" 可能拆成 token+ization）。这样词表不会爆炸，任何新词也能用子词拼出来。

中文贵的原因是个**训练数据配比问题**：主流词表以英文语料为主训练，中文语料占比低，所以英文常用词合得很充分（1 个单词约 1.3 token），而中文合并得不够——一个常用汉字常需 1~2 token，生僻字甚至被拆成 3 个"字节 token"（不表意的碎片）。结果：同样一篇 1000 字的文章，中文 token 数往往是英文同等内容的 1.5~2 倍。（国产模型如 Qwen、DeepSeek 扩了中文词表，中文 token 效率已明显更好。）

陷阱：说清影响——成本、上下文窗口有效容量、生成速度都按 token 计，中文贵是三样全贵。加分点：知道词表大小（10 万级）和 byte-level BPE（兜底保证任何输入——包括 emoji、乱码——都能编码，不会出现"无法表示的字符"）。

**Q4. 上下文窗口是什么？超长文档怎么办？**

一句话：上下文窗口是模型一次能"看到"的最大 token 数（含输入+输出），超长文档要靠检索（RAG）、分块处理（map-reduce）、或上下文压缩。

展开：把窗口想成模型的"办公桌面积"——桌上放不下的文件，模型不是"记住了一部分"，而是**完全不知道它存在**。一个 200 页 PDF 超过窗口时，超出部分等于没给。

处理手段按生产优先级：

1. **RAG**——先检索，只把相关片段放上桌（生产首选，便宜且准）；
2. **分层摘要 / map-reduce**——每块先各自摘要，再把摘要汇总给模型（适合全文都要用到、检索不好切的场景）；
3. **滑动窗口 + 增量处理**——按窗口滚过去逐段处理、累积状态；
4. **换长上下文模型**——注意长窗口 ≠ 长窗口内性能好，见下面的陷阱。

陷阱：面试官爱追问"窗口 128k 是不是就能直接塞一本书？"——要答：能塞但效果会掉（lost in the middle：模型对开头和结尾敏感，中间大段信息容易被忽略）、成本按 token 涨、延迟变长，生产上 RAG 通常又便宜又准。"能塞"和"塞了好用"是两回事。

**Q5. temperature / top_p / top_k 控制什么？**

一句话：三者都控制采样的随机性。temperature 按"浓度"缩放整个概率分布，top_k 只保留概率最高的 k 个词，top_p 只保留累计概率达 p 的最小词集（nucleus sampling）。

展开：模型每步输出的是**全词表的概率分布**（比如"猫"0.4、"狗"0.3、"车"0.1……），采样参数决定"从这个分布里怎么挑下一个词"：

- **temperature**（改分布本身）：除以一个温度系数再 softmax。T→0：概率差距被放大到极端，几乎每次都选第一名（贪心，稳定可复现）；T 调高：差距被抹平，低概率词机会变大（多样、有创意，但易跑偏）。类比：T 低像考试只写标准答案，T 高像头脑风暴什么都敢说。
- **top_k**（改候选集，固定大小）：只在概率最高的 k 个词里采样，k=50 就是把长尾全部砍掉。
- **top_p**（改候选集，自适应）：按概率从高到低累加，凑够 p（如 0.9）就截断。分布很尖时可能只留 3 个词，分布很平时留几百个——比 top_k 更聪明的"砍长尾"。

实践默认：问答/结构化输出 `temperature=0~0.3`（要稳定）；文案创作 0.7~1.0；代码生成 0~0.2。

陷阱：temperature 和 top_p 别同时大幅调（两者都在改采样行为，叠加容易失控）；判断题考"temperature 越低越有创意"——反了，越低越死板。

**Q6. 幻觉为什么会产生？**

一句话：根因是 LLM 的训练目标是"预测最像样的下一个词"，不是"输出真实"——它是个概率补全器，遇到知识空缺时会生成统计上流畅但事实上错误的内容，且无法自己区分知道与不知道。

展开：关键在于模型内部**没有"事实核查"这个环节**，只有"像不像"这个判断。三层原因：

1. 训练目标不奖励事实性——一个编得流畅的答案和真答案在 next token prediction 里拿同样的分数；
2. 知识有截止日期、长尾知识覆盖稀疏——问它训练数据里没怎么出现过的东西，它只能"按统计规律编一个最像的"；
3. 解码采样本身有随机性——同一问题问两遍，答案都可能不同。

典型诱发场景：提问里含错误预设（"为什么张三 1990 年退学？"——模型顺着编原因，而不是纠正前提）、要求引用论文/法条（会现编一条格式完全正确的假文献）、知识边界外的问题。

生产缓解手段，按层次：RAG（把事实资料直接给它，让它"照着抄"而不是"凭记忆"）、允许说"不知道"（prompt 约束 + 微调）、引用溯源（每个结论挂出处，可点击验证）、生成后校验（另一次调用专门核查事实，见 Q113）。

加分点：说出"幻觉无法根除，只能通过架构和流程把概率压低 + 影响限制住"这种工程视角，比背成因更加分。

**Q7. Embedding 是什么？为什么用余弦相似度？**

一句话：Embedding 把文本映射成高维向量，语义相近的文本向量方向相近；余弦相似度只比较方向不比较长度，更适合比较语义。

展开：把 embedding 想成给每段文本发一个"语义坐标"：训练目标是"让语义相近的句子在向量空间中靠近"——"怎么退货"和"退款流程是什么"字面几乎不重叠，但训练后两个向量会挨得很近，这就是语义检索能工作的原因。

为什么是余弦而不是别的距离？余弦相似度 = 两个向量夹角的余弦，范围 [-1,1]，**只看方向、不看长度**。而文本长度、词频会影响向量的模长（一段长文的向量天然"更长"），但长度本身不代表语义差异——"怎么退货"和一篇包含同样问题的长文档，语义方向应该一致。用余弦就把"语义是否相近"和"文本有多长"解耦了。

工程备注：很多向量库会先把向量归一化（长度变成 1），此时内积 = 余弦，用内积纯粹是因为算得快。

陷阱/加分点：能说出典型维度（768/1024/1536/3072）和"embedding 模型本身也是 Transformer，把整段文本编码后池化成一个向量"。

**Q8. 一次调用的成本和延迟由什么决定？**

一句话：成本 ≈ 输入 token 单价 × 输入量 + 输出 token 单价 × 输出量（输出单价通常是输入的数倍）；延迟 ≈ 排队 + prefill（处理输入）+ 逐 token 解码时间。

展开：**为什么输出 token 更贵**（有的贵 3~5 倍）？生成是自回归的：一个 token 接一个 token 吐，每吐一个都要把全部 KV cache 读写一遍、跑一遍整个模型——算力和访存都贵；而输入是一次性**并行**处理的（prefill，1000 个 token 一次矩阵运算算完），又便宜又快。打个比方：读一本书可以一目十行，但写读后感只能一个字一个字写。

由此得出优化优先级（先砍贵的）：

1. **输出长度**——限制 max_tokens、prompt 里要求简洁，砍 1 个输出 token 抵砍好几个输入的；
2. **重复输入**——system prompt、few-shot 示例这类每次都一样的内容用 prompt cache，缓存命中部分按大幅折扣计费；
3. **模型档位**——能小则小（见 Q11）。

延迟的两个核心指标：**TTFT**（首 token 时间，用户"等它开始说话"的体感）和每 token 输出速度（吐字速度，决定"说完整句"要多久）。用户总感知 ≈ TTFT + 总输出长度 ÷ 吐字速度——所以流式输出（先让字出来）能大幅改善体感，即使总耗时不变。

**Q9. 预训练 → SFT → RLHF 各解决什么？**

一句话：预训练学语言和世界知识（完形填空式），SFT 学"听懂指令、按格式回答"，RLHF/DPO 学"哪种回答人类更喜欢"（对齐）。

展开：三个阶段像培养一个新员工：

1. **预训练 = 读了整个图书馆**。用海量无标注文本做 next token prediction，学到了语言规律和世界知识。但产出的是一个"会说话但不听指挥"的基座——你问它"法国首都是哪"，它可能接着续写"那德国呢？意大利呢？"，因为它只见过"文章接着往下写"，没见过"问题要被回答"。
2. **SFT = 岗前培训**。用几万~百万条人工写的"指令→高质量回答"对做监督微调，教会它：问题是等回答的、要按人期望的格式来。参数量小改动，主要是"唤醒"预训练里已有的能力。
3. **RLHF = 树立价值观**。人类对同一问题的多个回答**排序**（比直接写答案便宜得多）→ 用排序数据训练一个奖励模型（学会打分"人类会喜欢哪种回答"）→ 用 RL（PPO）优化主模型去最大化这个分数。DPO 是简化版：跳过奖励模型和 RL 循环，直接用"好回答 > 坏回答"的偏好对训练，训练更稳更便宜（详见 Q95）。

一句话总结分工：预训练给能力，SFT 给格式，RLHF 给偏好对齐。

陷阱/加分点：能说出"RLHF 为什么用排序而不是让人写标准答案"（写答案贵且人与人风格不一，比较相对便宜且一致）；以及 SFT/RLHF 数据量远小于预训练（万级 vs 万亿 token），因为只是微调行为不是灌知识。

**Q10. repetition_penalty 和 logit_bias 干什么的？**

一句话：repetition_penalty 惩罚已出现过的 token 降低其概率，防止复读机；logit_bias 直接给指定 token 的 logits 加/减一个偏置，硬性提高或禁止某些词。

展开：复读是解码采样在高 temperature 之外的另一类失败——模型对刚输出过的词概率仍然偏高（统计上"接着重复"确实合理），于是陷入循环："很好很好很好……"。repetition_penalty（常见 1.0~1.2）对**已经出现过的 token** 按出现次数打折概率，打断循环；但设太强会伤语法——正常的虚词（"的""了"）本来就该高频出现，被惩罚后模型会硬换同义词，产出"该文章之内容极为优异"式怪腔。

logit_bias 是更直接的工具：不分析上下文，直接给指定 token 的 logits 加/减一个数。典型用途：禁止模型输出某词（bias=-100 基本封死该 token）、提高 JSON 结构词的概率来稳定格式。它是"硬控制"，repetition_penalty 是"软引导"。

陷阱：两者都不要过度调；另外 logit_bias 按字面 token 生效，想禁止一个概念时要覆盖它的各种写法（大小写、子词切分），实践中常顾此失彼。

**Q11. 给业务场景怎么选模型？**

一句话：按"任务难度 × 数据敏感性 × 预算 × 延迟要求"四维决策，先便宜的，跑评测，不达标再升级。

展开：给一个能直接在面试白板上画的决策顺序：

1. **数据能出内网吗？** 不能（金融/医疗/企业敏感数据）→ 直接锁定私有化开源模型（Qwen/DeepSeek 系），云端再好也出局；
2. **任务有多难？** 分类、抽取、格式转换这类简单任务 → 小模型/便宜模型，又省钱又快；复杂推理、Agent、长程规划 → 旗舰模型或推理模型（见 Q15）；
3. **有候选名单后，用自己业务的评测集跑分**（Q109）——公开榜单是别人的任务分布，你的客服工单分类榜单第一名未必好使；
4. 再叠加考虑：上下文长度需求、是否要多模态、生态质量（function calling 支持得好不好直接影响 Agent 可用性）。

一句话框架："先便宜的，跑评测，不达标再升级"——升级要拿评测数字说话，不是拍脑袋。

陷阱：只报模型名不给决策框架是减分的（模型半年一换，框架才是能力）。加分点：说"先建评测集再选模型"以及"大小模型路由省钱"（简单请求走小模型，难的才路由给大模型，综合成本降一个量级）。

**Q12. MoE 原理？为什么便宜？**

一句话：MoE 把 FFN 层换成多个"专家"子网络，每个 token 只被路由到其中 1~2 个专家计算——总参数量大，但每个 token 的实际计算量小，所以推理便宜。

展开：稠密模型里每个 token 都要过完整的 FFN——相当于每个问题都让全公司所有人参与。MoE 的做法：

1. 把每层 FFN 复制成 N 份，每份叫一个"专家"（其实就是一个独立的 FFN 子网络）；
2. 加一个**门控网络（router）**：对每个 token 算出"该找哪个专家"，只选 top-k（通常 1~2 个）；
3. 只有被选中的专家参与这个 token 的前向计算，其余专家闲着。

为什么便宜？算一笔账：DeepSeek-V3 总参数 671B，但每个 token 只激活约 37B——**显存要装下 671B（容量成本），计算只花 37B 的钱（算力成本）**。相当于养一个 671 人的公司但每个订单只动用 37 人，比同样每次全员的稠密模型省了一个量级的算力。

代价：① 所有专家都得装进显存，显存需求反而比同计算量的稠密模型大；② router 要处理负载均衡（不能所有流量都涌向一个专家）；③ 多机部署时专家分布在不同机器上，通信开销影响吞吐。

陷阱：被追问时澄清"便宜的是计算不是显存"——这是最常见的误解；MoE 的服务化部署门槛比稠密模型高。

**Q13. RoPE 是什么？为什么容易外推长度？**

一句话：RoPE（旋转位置编码）通过对 Q/K 向量按位置旋转特定角度来注入相对位置信息，注意力得分只依赖相对距离，且可以外推/插值到训练长度之外。

展开：模型需要知道词的顺序（"猫追狗"≠"狗追猫"），位置编码就是给每个位置打的时间戳。RoPE 的做法很几何：

1. 把 Q、K 向量**每两个维度当成平面上的一个点**；
2. 位于位置 m 的 token，把这些点旋转 m·θ 角度（θ 是每组固定的频率）；
3. 两个 token 的 Q、K 做点积时，旋转角会**相减**——结果只依赖两者的相对位置差 m−n，绝对位置消失了。

直觉：像表盘上的两根指针，它们的夹角只取决于时间差，不取决于几点钟。好处：无额外可学参数，且天然表达相对位置（语言关系本来就是相对的——"它"指代前文哪个词，看距离不看第几段）。

为什么容易外推？因为"位置"变成了角度，就有了一个可调的旋钮：**旋转频率**。训练时只见过 4k 位置，想支持 128k，就把频率整体放慢（NTK-aware scaling、YaRN 等），让"单位刻度"拉伸覆盖更长序列——相当于把地图比例尺缩小，老模型不用重训就能"看"到更大的范围。相对位置编码 + 频率缩放这两点，是 RoPE 成为现代 LLM 标配的原因。

P2 题，能说清"用旋转编码相对位置、可通过频率缩放外推"即可。

**Q14. 多模态模型怎么"看"图像？**

一句话：图像经视觉编码器（如 ViT）切成 patch 编码成向量序列，经投影层映射到与文本 token 同一空间，当作"图像 token"拼进上下文一起喂给 LLM。

展开：LLM 本身只认 token 序列，不认识像素——所以多模态的关键是"把图翻译成 LLM 能读的 token"。主流方案是三件套流水线：

1. **视觉编码器**（如 ViT）：把图像切成小方块（patch），每个 patch 类似一个"视觉词"，编码成向量序列；
2. **连接层（投影层）**：把这些视觉向量线性映射到与文本 token 相同的向量空间——让"图块向量"和"文字向量"说同一种语言；
3. **LLM**：把图像 token 和文字 token 拼成一条序列，正常做注意力。模型"看图回答问题"，机制上仍然是 token 序列上的补全——它不是真的"看"，是把图读成了它认识的一种文本。

由此能推出两个实际后果：① 一张图通常占几百~几千 token，这就是图片输入贵的原因（一张高清图抵几千字）；② 视频 = 抽帧后当多张图处理，token 消耗随帧数线性涨。

陷阱/加分点：被追问"那 OCR 呢？"——文字多的图未必需要视觉通路，很多生产系统对文档类图片仍走"先 OCR 成文本再给 LLM"的路线，更便宜更可控。

**Q15. 推理模型的 reasoning token 是什么？什么时候用？**

一句话：推理模型（o1/R1 类）在正式回答前先生成一段"思考"token（思维链），这些 token 同样计费同样耗时，换来在数学/代码/复杂推理上的显著提升。

展开：普通模型是"想到哪说到哪"——输出流里你看到的每个字都是它的思考过程。推理模型把这两步拆开了：先在内部生成一段很长的草稿（可能几千 token，逐步假设、验算、推翻重来），收敛后再输出正式答案。这个行为不是 prompt 出来的，是通过 RL 训练出来的（模型自己发现"多想几步再答，奖励更高"）。

成本账要会算：思考 token **照常计费、照常耗时**，输出 token 数翻几倍 → 延迟和费用大增。一个简单的客服分类问题让推理模型答，它可能"思考"800 token 才输出"退货"，纯浪费。

适用判断：

| 用 | 不用 |
|---|---|
| 多步数学、逻辑推理 | 简单分类、抽取 |
| 复杂 debug、代码重构 | 格式转换、模板化回复 |
| 长链路 Agent 规划 | 低延迟场景（<2s 响应） |

加分点：知道可以限制思考预算（如 reasoning_effort 参数）做成本/效果权衡——不是所有推理任务都值得让它"想到天荒地老"。
