# 七、微调与训练（参考答案）

---

**Q110. SFT 完整流程？数据格式？**

一句话：流程：定目标（想让模型改什么行为）→ 造数据（指令-回答对，质量>数量）→ 切 train/val → 训练（LoRA 起步，监控 val loss）→ 评测对比基座 → 部署。格式：chat 模板的多轮消息（system/user/assistant），或带 loss mask——只对 assistant 回答部分算 loss，不学用户输入。

展开：数据样例（LoRA 微调开源模型常用 Alpaca/ShareGPT 格式）：
```json
{"messages": [
  {"role": "system", "content": "你是差旅客服…"},
  {"role": "user", "content": "发票丢了怎么报销"},
  {"role": "assistant", "content": "分三种情况：…"}
]}
```
被追问最多的点：① 数据规模——行为对齐几百到几千条高质量样本常有感，知识灌注需要海量（那不如 RAG）；② loss mask 不做 → 模型在学习"生成用户的问题"，浪费容量。

**Q111. LoRA 原理？r/alpha？何时全参？**

一句话：冻结原权重 W，训练一个低秩增量 ΔW = B·A（A 降维、B 升维，秩 r ≪ d）——可训练参数从几十亿降到几百万~几千万，显存暴省，效果对行为类任务接近全参。r（秩，容量）常见 8~64；alpha（缩放系数）控制增量的"力度"，实际影响的是 alpha/r 的比值，加大 alpha ≈ 学得更激进。

展开：为什么低秩有效：微调的权重变化本质是低秩的（任务信息量有限）。工程优点：基座只存一份，多个 LoRA 适配器热切换（不同客户/任务一个基座）；可合并回基座无推理开销。什么时候全参：数据量大（10 万+）、任务和预训练分布差异大（领域 continue pretrain）、LoRA 扫参确实到不了标——代价是显存和算力数倍起。这题必须讲出"ΔW=B·A"这个式子。

---

**Q112. QLoRA 是什么？什么时候用？**

一句话：QLoRA = 把冻结的基座量化到 4bit（NF4）再挂 LoRA 训练——基座显存占用降约 4 倍，让单张 24G 消费级/工作站卡能微调 30B+ 模型。用在：预算/显存紧张、试错阶段的快速实验；代价：训练更慢、效果比全精度 LoRA 略降（通常可接受）。

展开：三个关键词：NF4（4bit 数值格式，为正态分布权重设计）、双重量化（连量化常数也量化，再省一点）、paged optimizer（显存峰值平滑）。面试官爱问"QLoRA 量化的基座会影响最终效果吗"——量化的是冻结基座，LoRA 增量仍以 bf16 训练；推理时可合并或保持量化，效果损失主要来自 4bit 基座本身，实践中对中小任务影响小。

**Q113. RLHF vs DPO？**

一句话：RLHF：训奖励模型 + PPO 强化学习优化，效果上限高但工程重（四个模型同时在显存里、训练不稳、超参敏感）；DPO：直接从"偏好对（chosen/rejected）"优化策略，绕过奖励模型和 RL 循环，简单稳定像 SFT 一样训——资源有限的团队首选，因此流行。

展开：理解 DPO 的巧思：数学上它等价于在隐式奖励下优化，把"训奖励模型"折叠进损失函数。选型：有强 RL 基建和大预算 → RLHF/PPO 仍是最优上限；大多数应用团队 → DPO/KTO（数据是二元好/坏标注时 KTO 更省，不需要成对）。加分点：知道两者都用"偏好数据"，数据质量同样是天花板——标注分歧大的偏好对是毒数据。

**Q114. prompt / RAG / 微调决策树？**

一句话：依次问：① prompt + few-shot 能解决吗？（最先试，几乎零成本）② 缺的是事实知识吗？→ RAG（可更新、可溯源）；③ 是行为/格式/风格不对，且 prompt 拉不动？→ 微调；④ 又缺知识又缺行为？→ 微调 + RAG 叠加。成本量级：prompt ≈ 0；RAG = 检索系统建设 + 每次查询的检索开销；微调 = 数据标注 + 训练 + 持续维护版本，最贵且知识会过期。

展开：一个反例常被追问："让模型学会我们公司的产品文档"该微调吗？——不该：文档天天更新，微调版永远滞后还无法溯源，RAG。反过来："让模型始终用我们品牌的语气、按固定工单格式输出"——prompt 试了不稳定、量大管不住 → 微调合适（行为稳定不过期）。把"知识会过期、行为不会"作为一句话总结。

**Q115. 微调数据从哪来？质量 vs 数量？**

一句话：来源四路：人工撰写（贵但准，用于种子和规范）、业务日志提炼（真实分布，需清洗脱敏）、强模型蒸馏合成（便宜量大，需人工抽检校准）、开源数据集（打底通用能力）。几百~几千条高质量数据足以改变行为模式；上低质万条不如精修千条——错误的示范会被忠实学习，垃圾进垃圾出。

展开：质量的具体判据：多样性（覆盖输入的真实分布和边界 case）、一致性（同场景的回答风格统一——多人写的数据风格漂移会让模型学成四不像）、正确性（事实错误直接教坏）。实操配比：先用 500 条试水验证管线通、效果方向对，再扩量。加分点：说"数据质量评测也是评测——先抽检数据再训练，比训练完才发现问题便宜得多"。

**Q116. 灾难性遗忘是什么？怎么防？**

一句话：微调把模型拉向新任务分布时，原有通用能力（对话、常识、推理）被"覆盖"式遗忘。防线：① 混入通用数据回放（replay，如混 10~30% 通用指令数据）；② LoRA 本身就是隔离（增量不改原权重，遗忘天然轻）；③ 小学习率 + 少 epoch，别把模型拧太狠；④ 评测必须含通用能力回归集。

展开：事故样例：用客服工单数据微调后，模型变得只会输出工单格式，正常聊天也往工单套——这就是拧过头了。诊断：训练前建一套"通用能力哨兵集"（常识问答、写作、数学各若干条），训练后跑，回退明显即过拟合或遗忘。工程心法："微调是手术不是重塑——切口越小（LoRA + 低 lr），恢复越快。"

**Q117. 怎么证明微调有效？含过拟合判断？**

一句话：三组对照评测：基座 vs 基座+prompt vs 微调版，在你的**业务评测集**（不在训练集里！）上比目标能力，同时在**通用回归集**上确保没退化；判过拟合：训练 loss 持续降但验证 loss 回升、或训练数据原句复述（背题）、或对训练分布外的输入崩坏——出现任一即停止/回退到更早 checkpoint。

展开："自欺欺人"的常见姿势（要主动避雷）：① 用训练数据评测（肯定好，无意义）；② 评测集和训练数据同源（同一批人写的，风格泄漏）；③ 只报目标指标不报退化指标（学会了一件事忘了十件事）。正确姿势：评测集来自真实用户请求抽样，训练前就冻结。一句话总结："微调报告必须有两列：目标能力涨了多少，通用能力掉了多少。"

**Q118. DeepSeek-R1 训练流程？应用侧启发？**

一句话：大致流程：基座 → R1-Zero 式纯 RL（可验证奖励：数学/代码对错直接给信号，模型自发长出推理链）→ 冷启动 SFT（整理高质量长推理数据）→ 多轮 SFT + RL 交替（推理 RL + 通用对齐 RL）→ 蒸馏到小模型（用 R1 生成推理数据 SFT 小模型）。应用侧启发：① 可验证任务（代码、数学）用推理模型收益最大；② 强模型的推理输出可以蒸馏给小模型（数据是免费的）；③ "测试时多想"（long CoT）是和"堆参数"正交的能力轴。

展开：这题 2025-2026 高频，考的是你是否跟得上前沿叙事，重点在**启发**部分而不是复述论文细节。能说出"RLVR（可验证奖励的 RL）让推理能力涌现"和"蒸馏数据让小模型也能推理"两个点就达标。

**Q119. 微调模型的部署与版本管理？**

一句话：像管理代码版本一样管理模型：训练任务记录（数据版本 + 超参 + 基座版本 + 评测报告）→ 产物（LoRA 权重）打版本 tag 入模型仓库 → 部署时基座 + LoRA 组合加载（多适配器热切换，一个基座服务多个 LoRA）→ 灰度放量 → 出问题秒级切回旧 tag。回滚 = 流量切回旧适配器，不需要重训。

展开：LoRA 的运维优势在这里兑现：基座部署一次，多个任务适配器像配置一样切换/回滚。要点：① 数据集也要版本化（DVC/对象存储 + manifest），否则"这个模型是用哪版数据训的"无法回答；② 评测报告随模型 artifact 存档——每个版本的"体检报告"可追溯；③ 合并版（merged 权重）用于追求极致推理性能的场景，但牺牲了热切换。
